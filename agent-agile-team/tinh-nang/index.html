Nói lời thường

Bạn mô tả việc muốn làm. Agent tự viết “làm gì” (SPEC) và “làm thế nào” (PLAN), rồi trình bản tóm tắt ngắn để bạn duyệt.

Chỉ bị hỏi hai lần

Cổng 1: duyệt hoặc điều chỉnh kế hoạch. Cổng 2: Đạt / Đạt có điều kiện / Không đạt. Agent hỏi lẻ giữa chừng là lỗi quy trình — bạn được quyền nhắc.

Người làm không tự chấm

Agent viết code không được tự kết luận “xong”. Một agent khác kiểm và ghi bằng chứng: lệnh đã chạy, kết quả thật.

Mọi việc đều có dấu vết

Mỗi yêu cầu, sprint, quyết định có mã và nằm trong tài liệu tra được.

Việc nhỏ đi đường nhẹ

Sửa một dòng chữ không cần bốn tài liệu. Bậc việc quyết độ dày hồ sơ.

32 skill và 13 agent

Skill là năng lực thường trực: agent rà danh mục trước mỗi hành động và tự gọi skill khớp tình huống.

6Quy trình 15Kỹ thuật 6Kiểm định 3Giao tiếp và tối ưu 2Meta
  • 19 skill kỷ luật có luật sắt, thử áp lực. 13 skill tham chiếu là bảng tra, thử truy xuất. Cả 32 đều có tệp thử đã chạy.
  • 12 agent chỉ đọc (reviewer theo ngôn ngữ, bảo mật, CSDL, săn lỗi bị nuốt…). build-fixer là agent duy nhất được sửa file — chỉ chỗ lỗi build đòi.
  • Skill quy trình trước, kỹ thuật sau. “Làm X” → định hình spec trước; “sửa lỗi” → debug trước.

Máy kiểm: init · check · index

Ba công cụ Python chỉ dùng thư viện chuẩn (3.9+), chạy trên Windows và macOS, không cần cài gói nào.

  • init dựng .agile.json, ba sổ gốc, khung sprint. Mặc định chạy thử, không bao giờ ghi đè.
  • check kiểm hồ sơ bằng 32 luật. Thoát 0 = Đạt, 1 = Không đạt, 2 = lỗi đầu vào.
  • check --self kiểm chính repo: lõi sạch, AGENTS.md ≤120 dòng và ≤10 KB, luật chống rò.
  • index sinh lại khối “Đang mở” ở đầu ba sổ gốc.

Sổ tập trung

  • Sổ Markdown ngoài repo, xem nhiều dự án ở một chỗ.
  • Bật bằng khoá ledger.project; đường kho sổ qua biến AGENT_AGILE_LEDGER.
  • Ghi ở năm thời điểm: mở sprint, qua Cổng 1, quay lại thực thi, Cổng 2, đóng sprint.
  • check bắt sổ lệch hồ sơ.

Chuẩn code

  • 7 chuẩn chung: phong cách, test, bảo mật, git, code review, quy trình phát triển, giao việc agent.
  • 4 chuẩn ngôn ngữ: python, typescript, react, web.
  • Không nạp vào luật lõi. Coverage mặc định 80 % cho code mới và code được sửa.

Quy tắc phiên bản

  • MAJOR.MINOR.PATCH, mỗi đợt tăng đúng một phần.
  • Dưới 1.0.0: thay đổi gãy chỉ tăng MINOR; chưa phát hành mang hậu tố -dev.
  • Agent đề xuất ở Cổng 2, bạn quyết. Không tự tăng version, không ghi đè CHANGELOG.

Nguồn gốc và giấy phép

  • Chưng cất từ các bộ skill mã nguồn mở (MIT): Superpowers, Everything Claude Code, gstack, superpowers-lab, Supabase Agent Skills; lấy ý từ GitHub Spec Kit, OpenSpec, BMAD-METHOD, Kiro/EARS.
  • Mọi skill và agent ghi source, source_sha, license; UPSTREAM.md chốt SHA từng đợt.
  • Phần từng lấy từ nguồn private đã viết lại phòng sạch; không còn file nào chờ viết lại.
  • Giấy phép của repo chưa chọn. Nội dung bên thứ ba giữ giấy phép gốc (NOTICE, THIRD_PARTY.md).
